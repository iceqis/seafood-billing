# 生产数据兼容性修复设计

## 背景

当前生产环境出现两类连锁故障：登录后首页可能显示“服务器内部错误”；新增客户的写入完成后，页面刷新阶段显示“飞书数据读取失败”，客户列表无法展示。现有五张飞书多维表格必须原样保留，不改字段、不迁移数据。

## 已确认根因

1. Worker 把飞书“筛选记录”请求发送到普通记录列表 GET 接口，并把筛选对象放在 URL 参数中；飞书筛选记录的正确契约是 `/records/search` 的 POST 请求，筛选对象放在 JSON 请求体中。
2. 订单和进货日期可能由飞书返回毫秒时间戳；统计服务却直接调用字符串方法，导致未捕获的类型错误并返回“服务器内部错误”。
3. 新增客户页面把“POST 写入”和“随后重新加载列表”放在同一个失败流程中。写入可能已经成功，但刷新失败时界面仍表现为添加失败，容易诱发重复提交。
4. 之前的生产检查只验证五张表能否无筛选读取，没有覆盖真实业务使用的订单筛选和统计映射，因此未能发现上述问题。

## 设计

### 1. 飞书读取协议

- 无筛选读取继续使用 `GET /records?page_size=500`。
- 有筛选读取使用 `POST /records/search?page_size=500`，请求体为 `{ "filter": ... }`。
- 单一筛选条件统一包装为 `{ conjunction: "and", conditions: [...] }`；已有组合条件保持不变。
- 两种读取都支持分页和仅针对安全、短暂读取故障的有限重试。
- 创建、修改、删除请求继续保持不重试，防止重复写入。

### 2. 日期兼容

- 在飞书字段映射边界统一规范日期，而不是让每个页面自行判断。
- 同时接受有效的 `YYYY-MM-DD`、ISO 日期文本、10 位秒时间戳、13 位毫秒时间戳。
- ISO 时间和时间戳按 `Asia/Shanghai` 转换成 `YYYY-MM-DD`，服务端默认当天也使用同一时区。
- 无效或空日期安全转换为空文本，保证统计筛选不会抛出类型异常。
- 对日期筛选结果再做一次本地精确过滤，以兼容现有表格中日期字段的实际存储类型。

### 3. 写入后刷新

- 客户 POST 成功后立即关闭弹窗并视为“保存完成”。
- 随后的列表刷新若失败，显示“客户已添加，但列表刷新失败，请刷新页面”，不能再误报为添加失败。
- 不自动重复 POST，不制造重复客户。

### 4. 错误可观测性

- 未识别的 Worker 异常记录安全类别信息（事件名与异常类型），客户端仍只收到通用提示。
- 日志不得包含飞书记录、密钥、密码、请求体或异常堆栈。

### 5. 生产验证

- 先部署一个临时、只读、全局限流且无业务数据返回的诊断入口，实际执行：客户列表、供应商列表、商品列表、订单单状态筛选、订单多状态筛选、当日订单筛选、当日进货筛选、首页统计。
- 诊断只返回各项成功/失败布尔值，不返回记录内容、字段值、表 ID 或密钥。
- 单项失败不会阻止后续检查，但响应会使用失败状态码阻断部署。
- 全部生产检查通过后，立即删除临时诊断入口并再次部署最终版本。

## 验收标准

- 登录后首页统计不再因数字日期报“服务器内部错误”。
- 客户页可以同时加载客户列表和多状态订单。
- 新增客户后能刷新列表；即使刷新遭遇短暂故障，也明确告知数据已保存且不会自动重复写入。
- 五张现有飞书表字段完全不变，无数据迁移。
- 单元测试、配置测试、端到端测试全部通过。
- 生产只读业务诊断全部通过，且最终版本不存在临时诊断入口。
