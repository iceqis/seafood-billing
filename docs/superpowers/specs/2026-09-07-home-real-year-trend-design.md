# 首页真实年度趋势图设计

## 目标

修复 QA-01：首页不得展示任何写死或模拟的经营数据。销售—进货图表必须只使用飞书五张现有表中的真实数据；当没有经营数据时明确显示“暂无经营数据”。

本次只处理 QA-01，不包含数据导出、删除约束、重复名称、历史日期跳转、批量确认预览或离线功能。

## 约束

- 保留现有原生 HTML、CSS、JavaScript、Cloudflare Worker、飞书多维表格和 GitHub Pages 技术栈。
- 完全兼容现有五张飞书表，不新增或修改字段，不迁移数据。
- 首页继续只发起一次 `/api/stats/home` 请求。
- 金额按现有规则保留两位小数。
- 年份和“当前月”由首页请求的 `date=YYYY-MM-DD` 决定，避免浏览器与后端时区不同导致月份范围不一致。

## 根因

当前 `index.html` 直接写入“1月 ¥12,000、2月 ¥8,500、3月 ¥15,200”和固定柱形宽度；`assets/js/pages/home.js` 只更新四张统计卡片；`worker/services/statistics.js` 的首页统计结果没有趋势数据。因此，无论飞书是否存在经营数据，固定示例都会留在页面中。

## 方案选择

采用“扩展现有首页统计接口”：在 Worker 已经读取订单和进货记录后，同时计算当年 1 月至请求日期当前月的趋势。前端用同一响应更新统计卡片和图表。

未采用独立趋势接口，因为它会让首页重复读取飞书数据；未采用前端聚合，因为它会传输不必要的原始数据，并使统计口径分散到前后端两处。

## 后端设计

`GET /api/stats/home?date=2026-09-07` 保留现有字段，并增加 `yearTrend`：

```json
{
  "todaySales": 0,
  "todayDealCount": 0,
  "todayPurchase": 0,
  "monthSales": 0,
  "yearTrend": [
    { "month": "2026-01", "sales": 0, "purchases": 0 },
    { "month": "2026-02", "sales": 1200.5, "purchases": 800 },
    { "month": "2026-03", "sales": 0, "purchases": 0 },
    { "month": "2026-04", "sales": 0, "purchases": 0 },
    { "month": "2026-05", "sales": 0, "purchases": 0 },
    { "month": "2026-06", "sales": 0, "purchases": 0 },
    { "month": "2026-07", "sales": 0, "purchases": 0 },
    { "month": "2026-08", "sales": 0, "purchases": 0 },
    { "month": "2026-09", "sales": 0, "purchases": 0 }
  ]
}
```

统计规则：

- 只生成请求日期所在年份的 1 月至当前月，不包含未来月份。
- 销售额只累加状态为 `unsettled`（未结算）或 `settled`（已结算）的订单金额，与现有首页销售口径一致。
- 进货额累加进货表记录金额。
- 其他年份记录、无效日期记录和不属于销售口径的订单不计入趋势。
- 没有记录的月份仍返回零值，使月份轴连续。
- 每个月的销售额和进货额分别四舍五入到两位小数。

## 前端设计

`index.html` 删除全部固定月份、金额和行内柱宽，仅保留图例和可动态渲染的容器，同时删除没有实际行为的“查看更多”按钮。

`assets/js/pages/home.js` 增加独立的趋势图渲染函数：

- 若 `yearTrend` 不存在、不是数组或所有月份的销售和进货金额均为零，容器只显示“暂无经营数据”。
- 若至少一个月存在非零金额，则渲染 1 月至当前月的全部月份。
- 每月同时显示真实销售额与真实进货额，金额格式统一为 `¥0.00`。
- 销售柱和进货柱共同使用响应中最大金额作为 100% 基准；零值柱宽为 0%，所有宽度限制在 0% 至 100%。
- 页面只通过 `textContent` 和安全 DOM 创建函数写入接口数据，不拼接不可信 HTML。
- 旧版后端若暂时没有 `yearTrend` 字段，前端显示“暂无经营数据”，绝不回退到示例数据。

## 错误处理

- 首页统计请求失败时沿用现有统一错误提示，不保留任何旧趋势内容。
- 每次发起首页加载时先清空趋势容器并显示加载后的真实结果，防止刷新失败时残留上一次金额。
- 非数字、负数或非有限金额在渲染时按 0 处理，避免异常柱宽破坏页面。

## 测试与验收

后端自动测试覆盖：

1. 返回请求年份 1 月至当前月的连续月份。
2. 仅“未结算、已结算”订单计入销售额。
3. 进货记录按月正确合计。
4. 排除其他年份和无效日期。
5. 空数据时每个月均为零。
6. 月金额按两位小数返回。

前端自动测试覆盖：

1. 使用接口 `yearTrend` 渲染月份、真实销售额、真实进货额和相对柱宽。
2. 全零、缺失或非法趋势数据时显示“暂无经营数据”。
3. 页面源码不再包含 `12,000`、`8,500`、`15,200` 等示例金额。
4. 首页进入时同时更新统计卡片和趋势图。

端到端验收：

- 模拟有数据时，首页展示与接口一致的当年月份和金额。
- 模拟无数据时，只显示“暂无经营数据”，页面中不存在固定示例金额。
- 桌面端和手机端图表不横向溢出。
- 完整前端、Worker、配置和浏览器流程测试全部通过。

## 非目标

- 不提供跨年切换或自定义日期范围。
- 不增加新的图表库或第三方 CDN。
- 不修改首页四张统计卡片的现有业务口径。
- 不处理 QA-02 至 QA-07。
