## 1. 项目概述

### 1.1 项目背景

本项目服务于一家海鲜批发零售商。客户群体以周边城市的海鲜零售商为主（约10个固定客户），同时存在少量个人零售。客户通常提前一天通过电话报货，第二天凌晨卸货、分拣、称重、发货，日终统一报价开单并结算。

此前一直使用**纸质账本**记录，存在以下核心问题：
- 进出货记录混乱，实际发货重量容易遗漏
- 账本不平，利润需要手动计算
- 手写开单复杂，效率低
- 客户结算周期不统一，人工翻账对账耗时且容易遗漏
- 多人同时操作时容易出错

### 1.2 项目目标

| 目标 | 说明 |
|------|------|
| **数字化** | 用网页替代纸质账本，所有订单、进货、客户、结算数据线上化 |
| **简化操作** | 针对60岁左右员工设计，界面极简、大字、大按钮，三步完成一单 |
| **账实一致** | 区分报货重量和实际发货重量，自动计算金额和利润 |
| **结算高效** | 按客户自动生成未结明细和结账单，支持多订单合并开单 |
| **数据安全** | 数据存储在飞书多维表格，云端备份，老板随时可查 |

### 1.3 技术方案

采用 **"免费优先、轻量可落地"** 的技术栈：

| 层级 | 技术 | 成本 | 说明 |
|------|------|------|------|
| 前端 | 单文件 HTML + 原生 CSS/JS | 免费 | 响应式网页，手机/电脑均可使用 |
| 后端 | Cloudflare Workers | 免费 | 每日10万次请求额度，足够 |
| 数据库 | 飞书多维表格 | 免费 | 云端存储，支持多人协作 |
| 部署 | GitHub Pages | 免费 | 获得可访问网址，手机微信点开即用 |

### 1.4 核心原则

1. **极简**：每个页面只做一件事，不超过3个主按钮
2. **大字**：18-20px字号，重要信息22-24px
3. **颜色状态**：用颜色区分状态，未处理=红色/橙色，已完成=绿色
4. **本地优先**：数据先存本地，有网后自动同步飞书（可选增强）
5. **离线可用**：基础页面可离线打开，网络恢复后同步

## 2. 业务背景与目标

### 2.1 业务场景

| 场景 | 描述 |
|------|------|
| **客户报货** | 前一天客户电话报货："明天要基围虾30头5斤"，员工记录 |
| **凌晨卸货** | 当天凌晨海鲜到货，记录进货量、成本价 |
| **分拣称重** | 按客户实际装货重量记录，可能损耗或增重 |
| **日终开单** | 汇总当天发货，按客户报价，生成总金额 |
| **周期结算** | 客户按周/月结账，老板筛选未结订单生成结账单 |

### 2.2 订单信息结构

**报货阶段**：品名、规格、报货重量
**发货阶段**：实际发货重量
**定价阶段**：单价（元/斤）
**开单阶段**：自动计算金额

### 2.3 核心痛点与解决方案

| 痛点 | 解决方案 |
|------|----------|
| 进出货混乱 | 订单与进货分离，各自独立记录 |
| 账不平 | 金额自动计算，未结金额自动汇总 |
| 记账时间长 | 预订单快速录入，称重/定价/开单流程化 |
| 手写复杂 | 点选客户/商品/规格，输入重量即可 |
| 实际发货遗漏 | 订单列表用红色标记未称重订单 |
| 结算翻账麻烦 | 客户模块一键生成未结明细，支持多选合并开单 |

## 3. 用户画像

### 3.1 角色定义

| 角色 | 使用场景 | 核心需求 |
|------|----------|----------|
| **老板** | 查看经营数据、审批开单、生成结账单 | 数据准确、一目了然、可导出 |
| **接电话员工** | 记录客户报货 | 操作简单、快速保存 |
| **分拣/称重员工** | 记录实际发货重量 | 大字、大按钮、快速输入 |

### 3.2 使用设备

- 主要使用**手机**
- 部分员工年龄约60岁，不擅长使用手机
- 秤数必须**手动输入**（无电子秤接口）
- 单据通过**截图/PDF**发送，无需现场打印

### 3.3 用户接受度

| 关注点 | 应对策略 |
|--------|----------|
| 员工学不会 | 界面按纸质账本逻辑设计，提供一页纸操作指南 |
| 网络不好 | 数据本地缓存，有网自动同步 |
| 数据丢失 | 飞书云端自动备份，支持导出Excel |

## 4. 核心业务流程

### 4.1 每日完整流程

```
前一天                          当天凌晨          白天              日终              结算时
  │                               │              │                 │                 │
  ▼                               ▼              ▼                 ▼                 ▼
客户电话报货 ──────────────────► 凌晨卸货 ─────► 分拣称重发货 ────► 一键生成报价单 ──► 选择周期出结账单
  │                               │              │                 │                 │
  │ 记录：                        │ 记录：        │ 记录：           │ 自动计算：       │ 勾选未结订单
  │ 客户 + 品名 + 规格 + 报货重量  │ 进货量+成本   │ 实际发货重量     │ 金额 = 重量×单价  │ 合并开单 → 结算
```

### 4.2 系统操作三步法

| 步骤 | 操作 | 耗时 |
|------|------|------|
| 第1步：接报货 | 首页 → 预订单 → 选客户 → 选商品/规格 → 输入报货重量 → 保存 | 30秒/单 |
| 第2步：称斤发货 | 订单 → 选日期 → 点击"去发货" → 输入实际重量 → 保存 | 20秒/单 |
| 第3步：日终开单 | 客户 → 选择客户 → 勾选未开单订单 → 统一开单 → 截图发客户 | 1分钟/客户 |

### 4.3 订单状态流转

```
┌─────────┐    保存    ┌──────────┐   发货填重   ┌──────────┐   输入单价   ┌──────────┐
│ 预订单  │ ─────────► │ 待发货   │ ─────────► │ 已发货   │ ─────────► │ 未开单   │
└─────────┘            └──────────┘            └──────────┘            └──────────┘
                                                                                │
                                                                                │ 客户模块：多选统一开单
                                                                                ▼
                                                                        ┌──────────┐   收款结算   ┌──────────┐
                                                                        │ 未结算   │ ─────────► │ 已结算   │
                                                                        └──────────┘            └──────────┘
```

### 4.4 业务流程说明

1. **预订单**：只含客户信息和商品信息（商品、规格、报货重量），保存后状态变为"待发货"
2. **待发货 → 已发货**：在订单模块点击"去发货"，输入实际发货重量，保存后状态变为"已发货"
3. **已发货 → 未开单**：在订单模块点击"去定价"，输入单价，系统自动计算金额，保存后状态变为"未开单"，同时订单从订单模块消失，自动转入客户模块
4. **未开单 → 未结算**：在客户模块勾选多个未开单订单，点击"统一开单"，合并为一张单据，状态统一变为"未结算"
5. **未结算 → 已结算**：在客户模块勾选未结算订单，点击"结算选中"，确认收款后状态变为"已结算"，复选框置灰

## 6. 订单状态机

### 6.1 状态定义

| 状态值 | 中文名 | 颜色 | 说明 |
|--------|--------|------|------|
| `pending_ship` | 待发货 | 橙色 | 刚保存的预订单 |
| `shipped` | 已发货 | 蓝色 | 已填实际发货重量，未定价 |
| `pending_bill` | 未开单 | 紫色 | 已定价，待客户模块统一开单 |
| `unsettled` | 未结算 | 黄色 | 已统一开单，待收款 |
| `settled` | 已结算 | 绿色 | 已收款结算 |

### 6.2 状态转换表

| 当前状态 | 操作 | 下一状态 | 触发页面 | 备注 |
|----------|------|----------|----------|------|
| - | 保存预订单 | pending_ship | 预订单 | 新建订单时 |
| pending_ship | 去发货，填实际重量 | shipped | 订单 | 订单列表中操作 |
| shipped | 去定价，填单价 | pending_bill | 订单 | 定价后自动转入客户模块 |
| pending_bill | 客户模块统一开单 | unsettled | 客户 | 可多选合并 |
| unsettled | 客户模块结算选中 | settled | 客户 | 可多选合并 |
| settled | 修改订单 | pending_bill | 客户 | 修改后状态重置为未开单 |
| pending_bill | 修改订单 | pending_bill | 客户 | 修改后保持未开单 |
| unsettled | 修改订单 | pending_bill | 客户 | 修改后状态重置为未开单 |

### 6.3 状态显示规范

- 订单模块只显示 `pending_ship` 和 `shipped`
- 客户模块显示 `pending_bill`、`unsettled`、`settled`
- 首页统计只统计 `unsettled` 和 `settled`（已成交）
- 已结算订单显示时透明度60%或置灰

## 9. 后端设计

### 9.1 架构图

```
员工/老板手机
      │
      ▼
  网页前端（GitHub Pages）

      ▼

      │  飞书 API 请求
      ▼
```

### 9.2 后端职责

| 职责 | 说明 |
|------|------|
| 转发前端请求 | 前端不直接调用飞书 API，避免暴露凭证 |

| 生成单号 | 订单号、进货单号由后端统一生成 |
| 错误处理 | 统一返回错误信息给前端 |
| CORS 处理 | 允许 GitHub Pages 域名访问 |

### 9.3 技术选型

- **Cloudflare Workers**：Serverless，免费额度足够
- **JavaScript (ES Modules)**：原生支持
- **Fetch API**：调用飞书开放 API

### 9.4 安全配置

| 配置项 | 说明 |

| 飞书 App ID / App Secret | 存储在 Cloudflare Workers 环境变量 |
| BASE_TOKEN | 多维表格标识 |

## 10. API接口规范

### 10.1 接口约定

- **Base URL**：`https://你的-worker地址.workers.dev`
- **请求方式**：RESTful
- **请求体格式**：JSON
- **响应格式**：JSON

### 10.2 通用响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

错误响应：
```json
{
  "code": -1,
  "message": "错误信息",
  "data": null
}
```

### 10.3 客户相关接口

#### 10.3.1 获取客户列表

- **GET** `/api/customers`
- 响应：
```json
{
  "code": 0,
  "data": [
    { "name": "小明", "phone": "13800138000", "settlement": "月结", "remark": "" }
  ]
}
```

#### 10.3.2 添加客户

- **POST** `/api/customers`
- 请求体：
```json
{
  "name": "小明",
  "phone": "13800138000",
  "settlement": "月结",
  "remark": ""
}
```

#### 10.3.3 删除客户

- **DELETE** `/api/customers/:name`
- 说明：删除客户不影响历史订单

### 10.4 供应商相关接口

#### 10.4.1 获取供应商列表

- **GET** `/api/suppliers`

#### 10.4.2 添加供应商

- **POST** `/api/suppliers`
- 请求体：
```json
{

  "remark": ""
}
```

#### 10.4.3 删除供应商

- **DELETE** `/api/suppliers/:name`

### 10.5 商品相关接口

#### 10.5.1 获取商品列表

- **GET** `/api/products`
- 响应：
```json
{
  "code": 0,
  "data": [
    { "name": "基围虾", "specs": "20头/30头/40头" }
```

#### 10.5.3 删除商品

- **DELETE** `/api/products/:name`

### 10.6 订单相关接口

#### 10.6.1 获取订单列表

- **GET** `/api/orders?date=2026-08-19&status=pending_ship,shipped`
- 参数：
  - `date`：日期，可选
  - `status`：状态，多个用逗号分隔，可选
  - `customer`：客户名称，可选

#### 10.6.2 创建预订单

- **POST** `/api/orders`
- 请求体：
```json
{
  "date": "2026-08-19",
  "customer": "小明",
  "product": "基围虾",
  "spec": "30头",
  "orderWeight": 5
}
```
- 后端行为：
  - 自动生成订单号 `XSD20260819001`
  - 状态设置为 `pending_ship`
  - 实际发货重量、单价、金额均为空

#### 10.6.3 更新订单（发货/定价/修改）

- **PUT** `/api/orders/:id`
- 请求体示例（发货）：
```json
{
  "actualWeight": 5.5,
  "status": "shipped"
}
```
- 请求体示例（定价）：
```json
{
  "price": 40,
  "status": "pending_bill"
}
```
- 请求体示例（修改）：
```json
{
  "actualWeight": 5.6,
  "price": 41,
  "status": "pending_bill"
}
```
- 后端行为：
  - 如果传入 `actualWeight` 和 `price`，重新计算 `amount = actualWeight * price`
  - 更新状态

#### 10.6.4 统一开单

- **POST** `/api/orders/bill`
- 请求体：
```json
{
  "ids": ["XSD20260819001", "XSD20260819002"],
  "customer": "小明"
}
```
- 后端行为：
  - 将指定订单状态批量更新为 `unsettled`
  - 返回合计金额

#### 10.6.5 结算订单

- **POST** `/api/orders/settle`
- 请求体：
```json
{
  "ids": ["XSD20260819001", "XSD20260819002"]
}
```
- 后端行为：
  - 将指定订单状态批量更新为 `settled`
  - 勾选"是否结算"

#### 10.6.6 删除订单

- **DELETE** `/api/orders/:id`

### 10.7 进货相关接口

#### 10.7.1 获取进货列表

1. 访问 [飞书开放平台](https://open.feishu.cn/)
2. 登录后创建"企业自建应用"
3. 获取 **App ID** 和 **App Secret**
4. 申请权限：
   - `bitable:app`（读取多维表格元数据）
   - `bitable:record`（读写记录）
5. 发布应用（测试版即可）

#### 11.2.2 创建多维表格

1. 登录飞书，新建"多维表格"
2. 创建 5 张表：客户表、供应商表、商品规格表、订单表、进货表
3. 按第 7 章配置字段
4. 获取每张表的 `TABLE_ID`（URL 中 `table=` 后的字符串）
5. 获取 `BASE_TOKEN`（URL 中 `base/` 后的字符串）

### 11.3 Cloudflare Workers 部署

1. 注册 [Cloudflare](https://www.cloudflare.com/) 账号
2. 进入 "Workers & Pages"
3. 创建新的 Worker
4. 粘贴 `cloudflare_worker.js` 代码
5. 设置环境变量：
   - `FEISHU_APP_ID`
   - `FEISHU_APP_SECRET`
   - `FEISHU_BASE_TOKEN`
   - `TABLE_CUSTOMERS`
   - `TABLE_SUPPLIERS`
   - `TABLE_PRODUCTS`
   - `TABLE_ORDERS`
   - `TABLE_PURCHASES`
6. 保存部署，复制 Worker 地址

### 11.4 GitHub Pages 部署

1. 注册 [GitHub](https://github.com/) 账号
2. 新建仓库，如 `seafood-billing`
3. 上传 `seafood_billing_web.html`
4. 进入仓库 Settings → Pages
5. Source 选择 `main` 分支
6. 等待几分钟后访问：`https://你的用户名.github.io/seafood-billing/seafood_billing_web.html`

### 11.5 前端配置

打开 `seafood_billing_web.html`，修改：

```javascript
const API_BASE = 'https://你的-worker地址.workers.dev';
```

### 11.6 员工使用

1. 将 GitHub Pages 链接发到员工微信群
2. 员工收藏链接到微信
3. 打开链接即可使用

## 13. 附录

### 13.1 订单号生成规则

- 销售订单：`XSD` + 日期（YYYYMMDD）+ 3位序号
- 进货单：`CGD` + 日期（YYYYMMDD）+ 3位序号

示例：`XSD20260819001`、`CGD20260819001`

### 13.2 状态枚举对照表

| 中文 | 英文值 | 颜色 | 允许操作 |
|------|--------|------|----------|
| 待发货 | `pending_ship` | 橙色 | 去发货 |
| 已发货 | `shipped` | 蓝色 | 去定价 |
| 未开单 | `pending_bill` | 紫色 | 统一开单、修改 |
| 未结算 | `unsettled` | 黄色 | 结算、修改 |
| 已结算 | `settled` | 绿色 | 修改（置灰） |

### 13.4 风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| 飞书API调用失败 | 数据无法同步 | 前端本地缓存，失败时提示重试 |
| 网络不稳定 | 操作中断 | 关键操作本地先保存，有网后同步 |
| 员工误操作 | 数据错误 | 删除和结算操作二次确认 |
| 飞书免费版限制 | 数据量过大 | 后期可升级或迁移至其他数据库 |
